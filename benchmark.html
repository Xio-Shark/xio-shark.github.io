实测数据：Agent 执行层故障注入与崩溃恢复

所有结论附方法与复现脚本。原始报告：harness-execution-audit.md · recovery-comparison.md

判定纪律（先读这个）。下面的故障注入审计用本地假端点回放固定磁带驱动各 harness——每个单元格确定、免费，但它陈述的是「harness 对一次脚本化工具调用的处理」，不是真实模型选调用时的行为。按既定纪律，任何第三方违规在被复现于真实模型之前不构成可报告的 finding。本页不构成对各产品的排名：不同 harness 违反的是不同属性，单格成立不能外推。

一、六个 harness 的执行层审计（2026-09-30 轮次）

问题：当工具调用底下出了故障，harness 说的和实际发生的一致吗？测试台用本地 HTTP 端点冒充模型服务、回放工具调用磁带，在沙箱中无头驱动每个 harness，注入故障，然后从机器外部（进程表、副作用账本、文件树）对照 harness 自己的说法（它回传给「模型」的工具结果）。

规模：442 次试验，11 类场景 × 9 个 harness 配置，每格 5 次（darwin arm64，Node v26.9.0）。只有 k/5 且 k ≥ 4 才算稳定判定。

被测版本：gemini-cli 0.46.0 · codex-cli 0.157.1 · opencode v2.0.16 · Claude Code 2.1.284 · qwen 0.24.7 · XioCode 1.6.0（xio 三个变体仅执行层不同）。

值得单独说的三条观察

  • 未观察到任何 harness 重复执行副作用。kill-mid-tool 中 effect_executions: 1 在所有臂成立，这是值得注意的好消息。差异主要体现在残留处理与历史记录：gemini 恢复后历史中该调用缺失；codex/opencode/qwen/claude 保留了调用但标记中断，且 1–2 个被打标进程在恢复后的会话里存活、未被提及。
  • orphan-at-exit 测的是执行层，不是 agent 循环。命令用 setsid 逃逸出自己的会话后，五个外部 harness 在会话结束 3 秒后均未清理该进程（5/5），也未在输出中说明。xio 三个变体里只有 reaper 驱动（枚举并收割离开进程组的后代）成立——同一个 agent 循环，换执行层，结果不同。
  • unconfirmed-stop 的停止确认问题。命令无视 SIGINT/SIGTERM 时，claude 报告「已停止」而被打标进程在会话结束后仍存活（5/5）。gemini 与 xio 各变体的 shell 工具没有时间上限参数，属性不可测，记 n/a。
这些结果不能推出：任何 harness 会重复副作用（未观察到）；产品排名；真实模型下的行为；其他平台 / 更新版本 / 沙箱加固选项开启时的表现；普通用户会话中必然可复现（这些是工具调用底下的刻意故障）。xio 的完整行是预发布构建上的历史测量（2026-09-30 后 UI 批次改变了交互与一次性模式的权限门），可引用的是 xio:node / xio:reaper 各格。

二、观测感知的崩溃恢复与 Early Cutoff（E4–E10）

问题：另一个 actor 改了工作区之后，被挂起的 agent 要么整个任务重来，要么复用仍然成立的历史前缀——记录中的观测在变化后的工作区里依然为真的那一部分。被测机制自动选择分叉点前最后一个完整检查点，重建前缀，只重算后缀。先验工作（2026-10-01 核对一手来源：AIOS、LangGraph time travel、Build systems à la carte、AutoGen）已覆盖检查点与回放；被检验的贡献是从变化的执行证据中自动选择有效恢复边界。

E9 日志压缩（边界性实验）

compact v2 编码使日志载荷相对完整状态对照缩减 70.2%（7,579,626 vs 25,457,438 字节，181 个状态事件），61 个检查点边界上恢复数据不变。口径：逻辑 JSON 字节，非文件系统/WAL 流量；耗时为小样本本地测量，不可外推。

E10 Early Cutoff 与目录树指纹跨分叉命令去重（确定性夹具）

E8 的阴性对照暴露了一个结构性瓶颈：coding agent 通常以宽泛的发现步骤（glob("**/*.ts")）或带行号的整文件读取开局。当并发事务新增了一个调用方文件或在文件顶部插入注释导致行号下移时，严格的原始输出哈希比较会让第 0 步或第 1 步直接失效，迫使整条 19 步轨迹从头重跑。E10 评估两项内核机制：

  • 观测重放 Early Cutoff（computeSymbolSliceCutoffHash + computeDiscoverySetCutoff）：剥离行号前缀与注释计算符号切片哈希，并将纯新增的发现集识别为可增量补做的超集；
  • 跨分叉目录树指纹命令去重（executeWorkspaceCommand + computeTreeCommandFingerprint）：将只读验证命令（如 tsc --noEmit）的操作指纹锚定在工作区文件树哈希而非分叉目录路径上，使并发分叉共享同一个 In-flight 或已记录的验证结果。
