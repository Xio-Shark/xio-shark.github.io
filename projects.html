xioflow · 面向多智能体并发的受监督执行内核

TypeScript · C (Linux subreaper / pidfd / macOS kqueue) · Linux cgroup v2 · SQLite (WAL) · npm: @xioflow/kernel

许多 Agent 运行时的执行层是 spawn() 加超时的简单封装：当宿主在工具调用中途崩溃、取消无法确认，或多个 Agent 并发修改同一工作区时，常留下逃逸孤儿进程、不可判定的副作用，以及粗粒度文件锁导致的整条轨迹作废重跑。xioflow 在进程树、工作区事务与观测日志三层提供内核级保证：

  • OS 级进程树管控与资源硬隔离：C 原生守护程序（xioflow-reaper.c）配合 Linux cgroup v2 驱动，在 Spawn Gate 挂载独立 cgroup 限制 memory.max / pids.max；以 PR_SET_CHILD_SUBREAPER + pidfd_send_signal（Linux）与 kqueue NOTE_FORK（macOS）收养并零竞态终止 setsid 双重 fork 逃逸孤儿；
  • 多 Agent 工作区乐观并发事务（OCC）：通过文件 atime 归一化实现零特权读集追踪，结合 git-shadow 写集差分做提交期后向冲突校验（Backward Validation）；
  • 观测级冲突消解与 Early Cutoff：文件级读写冲突时在临时分叉重放观测日志，通过 AST 符号切片哈希（剥离注释与行号偏移）和增量文件发现集实现 Early Cutoff，自动定位最大有效 Checkpoint 前缀并仅重算后缀（脚本化基准重做步骤 19→2、6→0）；
  • 跨分叉目录树指纹命令去重：以工作区文件树哈希锚定操作指纹（executeWorkspaceCommand），4 分叉并发执行 tsc --noEmit 时自动合并为单次进程（4→1）并支持不变工作区零派生复验（4→0）；
  • 三锁分离与诚实恢复：OS 排他锁 + SQLite WAL 写锁 + 资源租约，Epoch Fencing 代际栅栏隔离过期属主；结果不可判定时记为 indeterminate 并保留租约，绝不静默重放。

全仓 715 项测试通过（含 67 项编号黑盒 conformance 契约与无依赖 plain runner），配套 TLA+ 形式化规约与跨进程崩溃点注入矩阵，CI 覆盖 Node 22/24、Ubuntu 与 macOS。执行层正确性与恢复收益有公开的故障注入与崩溃恢复实验（E4–E10）背书。
